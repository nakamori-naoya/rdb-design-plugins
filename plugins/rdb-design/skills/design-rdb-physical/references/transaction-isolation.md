# 分離レベルは、許してはいけない業務の結果から選ぶ

分離性の設計は、同時に進む二つの業務の判断のあいだで、許してはいけない結果を先に決め、それを防げる手段を選ぶことである。分離レベルの名前から業務の規則を逆算しない。

## 分離する単位は、一つの業務の判断である

一つの SQL 文や一行の更新を守れても、一つの判断を守れるとは限らない。在庫を確かめて引き当てる、同じ時間帯に予約が無いことを確かめて予約を成立させる、といった処理では、読んだ複数の事実と、その結果として記録する事実が一つの判断を作る。transaction の境界はこの判断の境界から決める。人の応答や外部への通信を待つ部分は transaction の外に出し、事実を確かめ直して判断を確定する部分だけを短く包む。メールの送信や外部の決済のような RDB の外の効果は、分離性では一体にできないので、重複、遅延、再試行を別に設計する。

## 二つの業務を交差させて、許されない結果を見つける

正常系の一つの流れからは、要る分離性は見えない。同じ事前状態から始まる二つの業務の出来事を置き、それぞれが読む事実、下す判断、記録する事実を並べ、読む・判断する・記録する・確定するの節目を交互に並べ替える。その順序で両方を成功にしたときの最終状態が不変条件を破るなら、それが防ぐべき結果である。そのうえで、片方を拒む、繰り返す、順序を付ける、両方を成り立たせる、のどれを許すかを決める。

現象の名前は、候補を絞るのに使う。名前を書いたら、誰のどの判断がどう誤るのかも添える。

| 現象 | 最初に考える手段 |
|---|---|
| ダーティリード、ダーティライト | 少なくとも `READ COMMITTED` |
| 読み取りスキュー、ファントムリード | `REPEATABLE READ` 以上。同じスナップショットがどこまで守られるかを版で確かめる |
| ロストアップデート | 分離レベルだけで決めない。条件付き更新、版の検査、明示的なロック、製品の自動検出から選ぶ |
| 書き込みスキュー、直列化の異常 | `SERIALIZABLE` を候補にする。判断の前提になる読み取りと、それを覆す書き込みが同じ transaction にあるかを確かめる |

同じ分離レベルの名前でも、スナップショットの範囲、更新の競合の検出、範囲の保護は製品と版で違う。採る前に、対象の版の公式資料か再現試験で確かめる。

## 「まだ無いこと」を根拠にする判断は、一行の版では守れない

見落としやすいのは書き込みスキューである。会議室Aの10時から11時に予約が無いことを二人が同時に確かめ、それぞれ予約を記録すると、どちらの判断の時点でも既存の行は無い。無い行はロックできず、二人が足す行も別なので、行の競合では重複を防げない。件数の上限や重複の禁止も同じ形をしている。

このときは、まず排他制約や範囲の一意性のような、重なりそのものを拒む制約で守れないかを見る。固定の時間枠なら一意制約で足りるが、10時15分から10時45分のような任意の区間は開始時刻が違っても重なるので、区間の重なりを拒む制約が要る。次に `SERIALIZABLE` と transaction の中の繰り返しを比べる。集計の列を足して一行の問題に変える案は、元の事実から導ける情報をもう一つ持つことになるので、その後に比べる。資源と時間枠の行を先に作ってロックの対象にする案は、並行制御の都合を行として持ち込むので最後の候補にし、採るなら業務の事実ではない調整用のデータだと明記する。

`SERIALIZABLE` を採っても、失敗した transaction を業務上安全な単位で繰り返せなければ処理は完成しない。

## 分離レベルと繰り返しの回数は、物理設計が操作ごとに一つ決める

操作ごとに、分離レベルと、transaction の中で直列化の失敗やデッドロックを何回まで繰り返すかを書く。回数を使い切った失敗を、要求を回収し直す処理で通すかどうかは、実装のエラーの分類が決める。論理データモデルは許されない結果と競合する行の組までを書き、どう守るかは書かない。実装は、ここで決めた指定を transaction へ渡すだけで、自分で選ばない。持ち主が二つあると、論理は「実装が守る」と書き、実装は「資料に返す」と書いて、誰も決めない状態になるからである。

技術的な処理で要求を回収する操作は、回収の事実を追加する短い transaction にし、外部への通信をその外に置く。同じ要求を二つの送り手が同時に回収しないことは、回収の版の一意制約で守るのを既定にする。ロックを飛ばす読み取りは、待ち行列が長く一意制約の衝突が多すぎるときに足す。

必要以上に強い分離レベルは、待ちと競合と繰り返しを増やす。ただし、性能を理由に先に弱めてはいけない。許してはいけない結果を防げる選択肢の中で、対象の製品と負荷に合うものを選ぶ。
