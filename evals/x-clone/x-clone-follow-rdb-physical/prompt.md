X のクローン（X に似た SNS）の「フォロー」の業務について、RDB の物理設計の資料を新しく作ってください。対象の DBMS は PostgreSQL、版は 17.6 です。

## 入力

コマンドデータモデルは、この作業場所の `data-model/フォロー/command-data-model.md` です。クエリデータモデルは `data-model/フォロー/query-data-model.md` です。 同じ `data-model/` の下には、ほかの業務の業務知識とデータモデルも置いてあり、テーブルの持ち主を確かめるために読んでかまいません。どのデータモデルも書き換えないでください。

要求、利用規模と負荷、非機能要件は、`input/` の下の三つのファイルにあります。これは要件の文書で、要求発見、利用負荷モデル、品質要求の資料の形にはなっていません。基盤構成の資料と、実行計画や負荷試験などの検証の結果はありません。

## 保存先

資料は、作業場所の `out/フォロー/rdb-physical-design.md` に新しく保存してください（`out/フォロー/` のディレクトリは作ってかまいません）。skill が絶対パスを求めたら、作業場所の絶対パスを `pwd` で確かめて渡してください。

## ほかの package のファイル

この環境には write-doc と grill の skill が入っていません。代わりに、その最新のファイルを作業場所へ写してあります。skill が write-doc の template、見本、規範を読むよう求めたら `harness/write-doc/` の下を、grill の規律に従うよう求めたら `harness/grill/SKILL.md` を読んでください。

## grill の問いへの答え方

この実行には、問いに答える利用者がいません。あなたが利用者の代わりも務めます。skill が grill で問いを出したら、次の決まりで自分で答えてください。

- 渡した資料と要件にある事実で答えが決まるなら、その事実で答える。
- 資料と要件に無いことは、問いに添えた推奨を仮置きする。仮置きした答えは決定として本文で断定せず、資料の未決に、仮置きであること、根拠、採らなかった案、何が分かれば確定するかと一緒に書く。
- 推奨も無いときは、未決として残す。

問い、推奨、あなたの答え、その根拠（どのファイルのどの節か、推奨を仮置きしたか）は、出た順にすべて `grill-log/フォロー.md` に書いてください。grill の終わりの一覧への合意も、同じファイルに書いてください。問いが一つも無かったときも、そのファイルを作り、問わなかった理由を書いてください。

## 止まるとき

skill の停止条件に当たったら、skill の指示どおりに止まってください。止まったときは、何が分からず、それで結論のどこが変わるかを報告に書いてください。

## 報告

最後に、日本語で、保存した資料のパス、planned と未決の数、コマンドデータモデルへ差し戻した事項、grill の問いの数、検査の script の結果、途中で止まったならその理由を短く書いてください。
