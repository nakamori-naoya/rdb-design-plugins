# X のクローンのフォローに固有の条件

フォローのコマンドデータモデルは、二人の間のフォローを一つのリソースにしてイベントを積み、フォロー上限の5,000人を同時の要求でも超えないことを求め、フォローの変化の反映を技術処理の要求として積む。要件は、フォロー数の表示や読み取りの速さのために導いた値を持ちたくなる題材である。この条件は、そこでの判断を型にしたものである。

### follow-limit-concurrency

重み: 3

PASS：フォロー中が上限の手前のフォロワーが二人を同時にフォローする場面を、一行の競合では防げない判断として扱い、守る手段と繰り返しの回数を決めている。フォロー中の人数を数える列や表を足して一行の問題に変えるなら、それが業務の事実ではなく導いた値であることと、元の `follows` との整合の保ち方を書いている。

FAIL：上限の判断を、行の版の検査か一意制約だけで守れるとしている。または、フォロー中の人数の列や表を、導いた値としての説明（導く元、同期、作り直し、外し方）なしに足している。

### follow-no-count-as-fact

重み: 2

PASS：フォロー数やフォロワー数を表示や読み取りのために保存するなら、物理の判断として理由と整合の保ち方を添えている。保存しないなら、`follows` から数える読み取りと、それを支える index を書いている。

FAIL：フォロー数やフォロワー数を、コマンドデータモデルの事実のように説明なく保存している。

### follow-refollow-row

重み: 2

PASS：外した後にもう一度フォローしたときに、コマンドデータモデルが決めた保存の単位（同じ二人の組のリソースが戻り、版が進む）をそのまま写し、物理の都合で別の単位（外したら行を消す、フォローのたびに新しい行を作る）に変えていない。

FAIL：外した後の再フォローの扱いを、コマンドデータモデルと違う保存の単位に変えている。
