# ユーザータイムラインの業務知識

利用者が、自分または別の一人の利用者がこれまでにしたポストを、その人のものだけ新しい順に読むための業務知識である。業務を知る人と作り手が、誰がどのユーザータイムラインを見られ、何がどの順に見えるかを同じ例で判断できるようにする。この業務は利用者がユーザータイムラインを見ようとしたときに始まり、その人のポストが最初のポストまで新しい順に見えたところで終わる。業務を変える行いは持たず、ポストの業務が残したポストを読むだけである。

# 概要

ユーザータイムラインは、一人の利用者のポストを、その人がこれまでにしたものすべて、新しい順に見せる業務である。フォローしているかどうかにかかわらず、登録を済ませた利用者なら誰でも、自分のものも他者のものも見られる。フォローする前に相手がどんなポストをしているかを確かめたり、自分のポストを読み返したりできるのは、このユーザータイムラインがあるからである。一部のポストだけを見せたり、古いポストで打ち切ったりすると、その人が何をポストしてきたかを正しく判断できなくなるので、件数や経過した時間で見せる範囲を狭めない。

この業務はポストを作らず、変えもしない。ポストすることとポストの中身はポストの業務が、利用者の登録と利用者の見分け方はアカウントの業務が担う。自分とフォロー中の相手のポストをまとめて読むのはホームタイムラインの業務で、フォローするかどうかはフォローの業務が担う。初期リリースでは非公開アカウントとブロックとポストの削除を扱わないので、ユーザータイムラインから外れるポストは無い。

この業務は支援に置く。要件の初期リリースで提供する価値は、ポストし、フォローまたは解除し、自分のホームタイムラインを読めることで、ユーザータイムラインはその判断を助ける読み取りだからである（grill で推奨を採った）。

## 業務用語

### ユーザータイムライン

一人の利用者がこれまでにしたポストすべてを、新しい順に並べたものである。誰が見ても、同じ利用者のユーザータイムラインには同じポストが同じ順に並ぶ。自分とフォロー中の相手のポストをまとめたホームタイムラインとは違い、一人のポストしか含まず、見る人のフォローには左右されない。

### 対象利用者

ユーザータイムラインを見るときに、誰のポストを見るかとして指定された一人の利用者である。見る人本人のこともあれば、他者のこともある。見る人と対象利用者を分けて呼ぶのは、見られるかどうかを見る人で、何が見えるかを対象利用者で判断するからである。

## 業務イベント

この資料が持ち主の業務イベントは無い。ユーザータイムラインに何が見えるかは、ポストの業務の業務イベントで決まる。

# 概念

## ユーザータイムライン

ユーザータイムラインは、対象利用者が投稿者であるポストの集まりである。ポストの業務がポストを受け付けて成立させると、そのポストはその時点から対象利用者のユーザータイムラインに含まれる。初期リリースではポストの編集も削除も無いので、一度含まれたポストが外れたり中身が変わったりすることは無い。並びは新しい順で、これはポストIDの大きい順と同じ意味である。ポストした日時が後でもポストIDが小さければ後ろに並ぶ。

# 常に守られること

### 対象利用者がしたポストは、件数や経過した時間にかかわらずすべてユーザータイムラインに含まれる

一部が抜けたり、古いポストで打ち切られたりすると、見る人はその利用者がこれまで何をポストしてきたかを読み違え、フォローするかどうかを誤って判断する。対象利用者本人も、自分のポストを最初のポストまで読み返せなくなる。

### ユーザータイムラインには対象利用者のポストしか含まれない

ほかの利用者のポストが混ざると、見る人は誰がそのポストをしたのかを読み違える。

### ユーザータイムラインの並びは新しい順で、見る人によって変わらない

見る人ごとに並びが違うと、同じ利用者のポストについて話すときに、どれが先でどれが後かが食い違う。

# 状態と、その移り変わり

状態を持たない。この業務は業務を変える行いを持たず、ユーザータイムラインそのものも状態を持たない。

# 業務の行い

## コマンド

なし。

## クエリ

### ユーザータイムラインを見る

利用者登録を済ませた利用者なら誰でも、自分または存在する他者のユーザータイムラインを見られる。対象利用者をフォローしているかどうかは問わない。フォローする前に相手のポストを確かめられなければ、フォローするかを判断できないからである。利用者登録を済ませていない人は見られない。

見せるのは、対象利用者が投稿者であるポストのすべてで、一件ごとに、ポスト（ポストIDで一件に特定する）、投稿者、本文、ポストした日時を見せる。並べる順は新しい順、つまりポストIDの大きい順で、ポストした日時では並べ替えない。ポストが一件も無い利用者のユーザータイムラインは、何も並ばないユーザータイムラインとして正しく見える。

一回に見せる件数の上限（50件）と、続きを読むための位置の指定は、表示対象と並び順を変えないので API の契約に置いた。

#### 拒む理由: 利用者でない人がユーザータイムラインを見る

ポストは、利用者どうしが読み合うものとしてされている。利用者登録を済ませていない人に見せると、投稿者が想定していない相手にポストが読まれる。この理由は仮に置いたもので、要件は「登録済み利用者」だけが見られると決めているが、なぜかを書いていない。

#### 拒む理由: 存在しない利用者のユーザータイムラインを見る

いない利用者のユーザータイムラインを、ポストが無いユーザータイムラインとして見せると、見る人は、まだポストしていない利用者といない利用者を見分けられなくなる。

# 同時に起きたとき

なし。この業務は何も変えないので、ユーザータイムラインを見るのと同時にほかの行いが起きても、どちらかを通さないという判断は無い。見たときに成立しているポストが、その時点のユーザータイムラインである。続きを読んでいる間に成立したポストを先に読んだ部分へ加えないことは、続きを読むための位置の指定の約束として API の契約に置いた。

# まだ決まっていないこと

利用者でない人に見せない業務上の理由は仮に置いた。要件は見られる人を登録済みの利用者に限っているが、理由を書いていない。見られる人の決まりは変わらないので、理由の書き方だけをプロダクトの持ち主に確かめる。

一件ごとにポストした日時を見せるかは、grill で推奨を採って仮に置いた。要件は本文を見せることと、ポストした日時で並べ替えないことを書いているが、ポストした日時を見せるとは書いていない。プロダクトの持ち主に確かめる。

利用者、利用者ID、ポスト、ポストID、本文、投稿者、ポストした日時、新しい順の英名と種類は、持ち主の資料（[アカウントの業務知識](../アカウント/business-knowledge.md)、[ポストの業務知識](../ポスト/business-knowledge.md)）がまだ無いので照合していない。持ち主の資料ができたら、その英名に合わせる。新しい順をポストの業務が持つとしたのは、新しい順がポストIDの値で意味が決まる語だからである。

# BDD

ここまでの決まりが、具体の場面でどう働くかを示す。ポストIDは、番号の大きいほうが大きいポストIDを表す。

## ユーザータイムラインを見る

### [BDD-001] フォローしていない他者のユーザータイムラインは、その人のポストだけが新しい順に見える

```gherkin
Given: 利用者 U-0001 と利用者 U-0002 は利用者登録を済ませており、利用者 U-0001 は利用者 U-0002 をフォローしていない
  And: 利用者 U-0002 はポスト P-0001 を2026年10月1日 09:00に、ポスト P-0003 を同じ日の10:00にした
  And: 利用者 U-0003 はポスト P-0002 を2026年10月1日 09:30にした
When: 利用者 U-0001 が2026年10月1日 11:00に利用者 U-0002 のユーザータイムラインを見る
Then: ポスト P-0003、ポスト P-0001 の順に、投稿者、本文、ポストした日時と一緒に見える
  And: 利用者 U-0003 のポスト P-0002 は見えない
```

### [BDD-002] 本人のユーザータイムラインには、いましたポストも含めて自分のポストが見える

```gherkin
Given: 利用者 U-0002 は利用者登録を済ませており、ポスト P-0001 を2026年10月1日 09:00にした
  And: 利用者 U-0002 は2026年10月1日 11:00にポスト P-0004 をした
When: 利用者 U-0002 が2026年10月1日 11:01に自分のユーザータイムラインを見る
Then: ポスト P-0004、ポスト P-0001 の順に見える
```

### [BDD-003] ポストの無い利用者のユーザータイムラインは、何も並ばずに見える

```gherkin
Given: 利用者 U-0001 と利用者 U-0005 は利用者登録を済ませている
  And: 利用者 U-0005 はポストを一件もしていない
When: 利用者 U-0001 が利用者 U-0005 のユーザータイムラインを見る
Then: ポストが一件も無いユーザータイムラインが見える
```

### [BDD-004] 501件ポストした利用者のユーザータイムラインは、最初のポストまで読める

```gherkin
Given: 利用者 U-0001 と利用者 U-0002 は利用者登録を済ませている
  And: 利用者 U-0002 は、最初のポスト P-1000 を2026年1月5日に、以後ポスト P-1001 から P-1500 までを2026年10月1日までにした
When: 利用者 U-0001 が2026年10月2日に利用者 U-0002 のユーザータイムラインを最後まで読む
Then: ポスト P-1500 から P-1000 までの501件が、この順にすべて見える
  And: 最後に見えるのは最初のポスト P-1000 である
```

### [BDD-005] ポストした日時が後でもポストIDが小さいポストは後ろに並ぶ

```gherkin
Given: 利用者 U-0001 と利用者 U-0002 は利用者登録を済ませている
  And: 利用者 U-0002 のポスト P-0007 のポストした日時は2026年10月1日 10:00:02、ポスト P-0008 のポストした日時は同じ日の10:00:01である
When: 利用者 U-0001 が利用者 U-0002 のユーザータイムラインを見る
Then: ポスト P-0008、ポスト P-0007 の順に見える
```

### [BDD-006] 利用者登録を済ませていない人はユーザータイムラインを見られない

```gherkin
Given: Googleアカウントで本人確認された人 G-0009 は、利用者登録を済ませていない
  And: 利用者 U-0002 はポスト P-0001 をしている
When: G-0009 が利用者 U-0002 のユーザータイムラインを見る
Then: 何も見えない
  NOTE: Rule: 利用者でない人がユーザータイムラインを見る
    Reason: ポストは利用者どうしが読み合うものとしてされている
```

### [BDD-007] 存在しない利用者のユーザータイムラインは見られない

```gherkin
Given: 利用者 U-0001 は利用者登録を済ませている
  And: 利用者ID U-9999 の利用者はいない
When: 利用者 U-0001 が利用者 U-9999 のユーザータイムラインを見る
Then: ポストが無いユーザータイムラインとしても見えず、その利用者がいないことが分かる
  NOTE: Rule: 存在しない利用者のユーザータイムラインを見る
    Reason: まだポストしていない利用者といない利用者を見分けられなくなる
```
