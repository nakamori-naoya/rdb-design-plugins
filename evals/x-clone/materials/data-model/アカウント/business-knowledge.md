# アカウントの業務知識

利用を始めたい人がGoogleアカウントで利用者として登録し、次からは同じGoogleアカウントで同じ利用者として戻ってこられるようにするための業務知識である。業務を知る人と作り手が、誰が利用者で、どのGoogleアカウントが誰なのかを同じ言葉で判断するために読む。この業務は、利用希望者がGoogleアカウントで本人確認されたところから始まり、利用者として登録したとき、またはログインして自分がどの利用者かが分かったときに終わる。

# 概要

アカウントの業務は、一つのGoogleアカウントを一人の利用者に結びつけ、ポスト、フォロー、タイムラインを読む人が誰なのかを一つに決める業務である。利用希望者はGoogleアカウントで本人確認されたときにだけ利用者として登録でき、登録は一つのGoogleアカウントにつき一度きりである。次からは、同じGoogleアカウントでログインすれば同じ利用者として扱われる。こうして誰が何をしたかが一人の利用者に集まるので、ほかの利用者の名前でポストしたり、他人のホームタイムラインを読んだりすることを防げる。

この業務が守りたい価値は、利用者が重ならず、入れ替わらないことである。同じGoogleアカウントから利用者が二人生まれると、ポストとフォローが二人に割れ、本人が自分の続きを見失う。メールアドレスが同じというだけで別のGoogleアカウントを一人にまとめると、別人が他人の利用者として振る舞えてしまう。だから、同じ利用者かどうかはGoogleアカウントだけで決める。

この業務は、プロダクトの中心である「フォローした相手のポストを読む」ことを支える入口なので、支援の業務と位置づける。Googleアカウントに限ることと、メールアドレスで統合しないことがこのプロダクト固有の決まりであり、どこにでもある汎用の認証とは言い切れないからである。

この業務は、ポスト、フォロー、タイムラインの行いそのものを担わない。フォローする相手を探すための登録済み利用者の一覧は[フォローの業務](../フォロー/business-knowledge.md)が担う。表示名やプロフィール画像の管理、本人退会、退会後の再登録、強制退会、復旧と異議申立て、Googleアカウントの付け替えは、初期リリースでは扱わない。Googleアカウントの本人確認をどの製品で行うか、確かめた結果をどう持ち回るかは、仕組みの関心であり、この資料には書かない。

## 業務用語

### 利用希望者

このサービスを使い始めたい人で、まだ利用者として登録していない人である。Googleアカウントで本人確認されていても、登録するまでは利用者ではない。利用希望者が行えるのは、利用者として登録することだけである。

### 利用者

Googleアカウントで利用者として登録した人である。ポストし、フォローし、タイムラインを読めるのは利用者だけである。一人の利用者は、登録したときのGoogleアカウント一つと結びつき、その結びつきは初期リリースの間変わらない。

### 利用者ID

利用者として登録したときにこのサービスが一人ずつに付ける、利用者を一人に特定する番号である。登録した後は変わらない。ほかの業務は、誰のポストか、誰が誰をフォローしているかを、この番号で指す。要求の中に書かれた利用者IDを名乗っても、それだけではその利用者として扱わない。誰であるかは、ログインしたGoogleアカウントから決まる。

### Googleアカウント

利用希望者と利用者が、自分が誰であるかをこのサービスに示すために使う、Googleの一つのアカウントである。このサービスは、Googleアカウントで本人確認された人だけを登録とログインで受け付ける。二つのGoogleアカウントは、メールアドレスが同じでも別のGoogleアカウントであり、別の人として扱う。

### 登録日時

利用希望者が利用者として登録した日時である。登録の事実を後から説明するときに、いつ利用者になったかを示すために使う。

## 業務イベント

### 利用者として登録した

利用希望者が、本人確認されたGoogleアカウントで利用者として登録した。新しい利用者が生まれ、利用者IDが付き、そのGoogleアカウントはこの利用者に結びつく。以後、そのGoogleアカウントからは新しい利用者を登録できなくなり、ログインすればこの利用者として扱われる。

# 概念

## 利用者とGoogleアカウントの結びつき

利用者は、登録したGoogleアカウントと一緒にだけ存在する。利用者として登録すると、利用者とそのGoogleアカウントの結びつきが同時に生まれ、片方だけが生まれることはない。結びつきは一対一で、一つのGoogleアカウントは一人の利用者にだけ、一人の利用者は一つのGoogleアカウントにだけ結びつく。ログインで誰であるかを決めるときは、この結びつきをたどる。

# 常に守られること

### 一つのGoogleアカウントからは、一人の利用者しか生まれない

同じGoogleアカウントから利用者が二人生まれると、本人のポストとフォローが二人に割れ、ログインするたびにどちらの利用者になるかが定まらない。本人は自分のポストやフォローした相手を見失う。

### 利用者は、登録したGoogleアカウントと結びついたまま存在し、片方だけにはならない

Googleアカウントに結びつかない利用者は、誰もその利用者としてログインできないまま残る。利用者のいないGoogleアカウントの結びつきは、そのGoogleアカウントの持ち主を登録済みと扱いながら、使える利用者を渡さない。どちらも本人がサービスを使えなくなる。

### 同じ利用者かどうかはGoogleアカウントで決め、メールアドレスでは決めない

メールアドレスが同じ別のGoogleアカウントを一人の利用者にまとめると、そのGoogleアカウントの持ち主が他人の利用者としてポストし、フォローできてしまう。他人の名前で行われたポストとフォローは、元の利用者の信用を損なう。

### 利用者として登録していない人は、利用者として振る舞えない

Googleアカウントで本人確認されていても、登録していない人がポストやフォローをすると、その行いが誰のものかを利用者IDで示せない。ほかの利用者は、誰のポストを読み、誰にフォローされたのかが分からなくなる。

### 誰が、いつ、どのGoogleアカウントで利用者として登録したかを後から説明できる

運営者は、利用者から「自分はいつ登録したのか」「なぜ別の利用者にならないのか」と問われたとき、その利用者がいつどのGoogleアカウントで登録したかを示して答える。説明できなければ、一つのGoogleアカウントから一人しか生まれないという決まりが守られていることを示せない。誰が何を説明するためかは要件に書かれていないため、この目的は仮説として置いている（「まだ決まっていないこと」を参照）。

# 状態と、その移り変わり

## 利用者は状態を持たない

状態を持たない。初期リリースで利用者に起きる業務イベントは「利用者として登録した」だけで、登録した後に利用者を変える行い（退会、強制退会、付け替え）は扱わないからである。

# 業務の行い

## コマンド

### 利用者として登録する

Googleアカウントで本人確認された利用希望者本人だけが、そのGoogleアカウントで利用者として登録できる。他人のGoogleアカウントで登録できると、そのGoogleアカウントの持ち主は、後から自分のGoogleアカウントでログインしたときに、他人が作った利用者として扱われ、身に覚えのないポストやフォローの責任を負う。

登録できるのは、Googleアカウントで本人確認され、そのGoogleアカウントがまだどの利用者にも結びついていないときである。登録すると新しい利用者が生まれ、利用者IDが付き、そのGoogleアカウントがこの利用者に結びつき、「利用者として登録した」が起きる。登録日時は登録した日時である。同じメールアドレスの利用者がすでにいても、Googleアカウントが違えば別の利用者として登録できる。登録は一つのGoogleアカウントにつき一度きりで、すでに結びついているGoogleアカウントからの登録は、応答を受け取れずに繰り返した場合も含めて拒む。

#### 拒む理由: Googleアカウント以外の方法で登録する

このサービスは、利用者が誰であるかをGoogleアカウントでだけ確かめる。LINE、GitHub、パスワード、メールのリンク、電話番号など別の方法で登録できると、同じ人がGoogleアカウントとは別に利用者を持てるようになり、一人から一人の利用者しか生まれないという決まりが守れない。

#### 拒む理由: 本人確認されていないGoogleアカウントで登録する

そのGoogleアカウントの持ち主であると確かめられていない人が登録すると、他人のGoogleアカウントで利用者を作れてしまう。本当の持ち主は、自分のGoogleアカウントで他人の作った利用者として扱われる。

#### 拒む理由: 利用者に結びついたGoogleアカウントで登録する

一つのGoogleアカウントから二人目の利用者を生むと、本人のポストとフォローが二人に割れる。登録は一つのGoogleアカウントにつき一度きりである。

## クエリ

### Googleアカウントでログインする

Googleアカウントで本人確認された本人だけが、そのGoogleアカウントでログインできる。他人がログインできると、その人は他人の利用者としてポストし、フォローし、他人のホームタイムラインを読めてしまう。

ログインで分かるのは、本人確認されたGoogleアカウントに結びついた利用者と、その利用者IDである。表示対象は、そのGoogleアカウントに結びついた利用者一人だけで、並び順は無い。要求の中に別の利用者IDが書かれていても、分かるのはGoogleアカウントに結びついた利用者である。ログインは業務イベントを起こさず、何度ログインしても利用者は増えない。

#### 拒む理由: Googleアカウント以外の方法でログインする

このサービスは、利用者が誰であるかをGoogleアカウントでだけ確かめる。別の方法でログインできると、Googleアカウントに結びつかない誰かが利用者として振る舞える。

#### 拒む理由: 利用者に結びついていないGoogleアカウントでログインする

Googleアカウントで本人確認されていても、利用者として登録していなければ利用者ではない。利用者として扱うと、その行いを誰のものとして示せばよいかが決まらない。その人が次に行えるのは、利用者として登録することだけである。

#### 拒む理由: 他人の利用者として名乗ってログインする

本人確認されたGoogleアカウントと違う利用者IDを名乗って、その利用者として扱われると、他人の名前でポストし、フォローし、他人のホームタイムラインを読めてしまう。

# 同時に起きたとき

### 同じGoogleアカウントから、利用者として登録するのが同時に二つ届く

先に受け付けた一つだけが通り、利用者は一人だけ生まれる。遅れたほうは、利用者に結びついたGoogleアカウントでの登録として拒まれ、二人目の利用者は生まれない。一つのGoogleアカウントからは一人の利用者しか生まれないからである。応答を受け取れずに繰り返した登録が、最初の登録と重なった場合も同じである。

# まだ決まっていないこと

「誰が、いつ、どのGoogleアカウントで利用者として登録したかを後から説明できる」の、説明する人と目的は仮説である。要件は利用者登録について成立した事実と現在状態を共に記録することを求めているが、誰が何を説明するためかを書いていない。運営者が利用者の問い合わせに答えるため、と仮に置いた。採らなかった案は、本人退会や付け替えのような後続の業務の起点として残す、という目的だけを書く案である。要件の持ち主（利用者）に確かめれば決まる。

利用者IDの付け方（どんな番号にするか）は、表示対象と並び順を変えないので、業務の決まりとしては置かない。

# BDD

ここまでの決まりが、具体の場面でどう働くかを示す。**ここに上で書いていない決まりを持ち込まない。** 利用者IDとGoogleアカウントの表記（U-0001、G-1001など）は例として置いた値である。

## 利用者として登録する

### [BDD-001] 本人確認されたGoogleアカウントで初めて登録すると利用者が生まれる

```gherkin
Given: 利用希望者は、Googleアカウント G-1001 の持ち主として本人確認されている
  And: Googleアカウント G-1001 はどの利用者にも結びついていない
When: 利用希望者が2026年10月1日 10:00にGoogleアカウント G-1001 で利用者として登録する
Then: 新しい利用者 U-0001 が生まれ、Googleアカウント G-1001 が利用者 U-0001 に結びつく
  And: 「利用者として登録した」が起き、登録日時は2026年10月1日 10:00である
```

### [BDD-002] メールアドレスが同じでも別のGoogleアカウントなら別の利用者が生まれる

```gherkin
Given: 利用者 U-0001 は、メールアドレス alice@example.com のGoogleアカウント G-1001 に結びついている
  And: 利用希望者は、同じメールアドレス alice@example.com のGoogleアカウント G-2002 の持ち主として本人確認されている
  And: Googleアカウント G-2002 はどの利用者にも結びついていない
When: 利用希望者が2026年10月2日 09:00にGoogleアカウント G-2002 で利用者として登録する
Then: 利用者 U-0001 とは別の新しい利用者 U-0002 が生まれ、Googleアカウント G-2002 が利用者 U-0002 に結びつく
  And: 利用者 U-0001 とGoogleアカウント G-1001 の結びつきは変わらない
```

### [BDD-003] 利用者に結びついたGoogleアカウントでは二度目の登録ができない

```gherkin
Given: Googleアカウント G-1001 は利用者 U-0001 に結びついている
  And: Googleアカウント G-1001 の持ち主は、G-1001 の持ち主として本人確認されている
When: Googleアカウント G-1001 の持ち主が2026年10月3日 10:00に再び利用者として登録する
Then: 新しい利用者は生まれない
  And: 利用者 U-0001 とGoogleアカウント G-1001 の結びつきは変わらない
  NOTE: Rule: 利用者に結びついたGoogleアカウントで登録する
    Reason: 一つのGoogleアカウントからは、一人の利用者しか生まれない
```

### [BDD-004] LINEでは利用者として登録できない

```gherkin
Given: 利用希望者は、LINEのアカウントで本人確認されている
  And: 利用希望者は、どのGoogleアカウントでも本人確認されていない
When: 利用希望者が2026年10月1日 11:00にLINEのアカウントで利用者として登録する
Then: 新しい利用者は生まれない
  NOTE: Rule: Googleアカウント以外の方法で登録する
    Reason: このサービスは、利用者が誰であるかをGoogleアカウントでだけ確かめる
```

### [BDD-005] 他人のGoogleアカウントを名乗っても利用者として登録できない

```gherkin

  And: Googleアカウント G-3003 はどの利用者にも結びついていない

  And: Googleアカウント G-3003 はどの利用者にも結びつかないままである
```
