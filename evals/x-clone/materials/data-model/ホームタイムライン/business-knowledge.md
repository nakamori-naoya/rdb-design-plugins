# ホームタイムラインの業務知識

利用者が自分のホームタイムラインを読んだとき、どのポストが見え、どの順に並ぶかを、業務を知る人と作り手が同じ例で同じ結論を出せるようにするための業務知識である。この業務は、利用者が自分のホームタイムラインを読んだときに始まり、見えるポストが新しい順に返されたときに終わる。ポストを作ることとフォローを変えることは隣の業務が担い、この業務はそれらが残した事実を読むだけである。

# 概要

ホームタイムラインは、利用者が自分のポストと、いまフォロー中の相手のポストを、新しい順にまとめて読むための業務である。利用者は読みたい相手をフォローし、その相手が何をポストしたかを一か所で追う。だから、何が見えるかは「いまフォロー中か」だけで決まり、いつフォローしたか、いつのポストかでは変わらない。フォローを外した相手のポストは、外す前のものも見えなくなる。利用者が読む相手を選び直せば、ホームタイムラインもそれに従う、という約束を守ることがこの業務の価値である。

ホームタイムラインには、誰をフォローしているかがそのまま映る。そのため、読めるのは本人だけである。

この業務はコマンドを持たない。ポストを作るのはポストの業務、フォローとフォローを外すのはフォローの業務、利用者として登録しログインするのはアカウントの業務が担う。本人のユーザータイムラインや他者のユーザータイムラインを読むのはユーザータイムラインの業務である。ポストがホームタイムラインへ届くまでの遅れ、キャッシュ、配信の要求、読み取りに失敗したときの扱いは、仕組みを変えれば消える関心なので、この資料の決まりには入れない。

業務の中での位置づけはコアである。利用者が何を見られるかがこのプロダクトの中心であり、ホームタイムラインの閲覧はポストのおよそ100倍行われる（利用規模と負荷モデル）。業務の状態を変えないからといって支援や汎用へは下げない。

## 業務用語

### ホームタイムライン

一人の利用者が、自分のポストと、いまフォロー中の相手のポストを新しい順に読む一覧である。利用者ごとに一つあり、その持ち主だけが読める。ユーザータイムラインが「ある一人の利用者のポスト」を読む一覧で、誰でも読めるのに対し、ホームタイムラインは「持ち主が読むと決めた相手」のポストを集めた一覧で、持ち主にしか見せない。見えるポストに件数や期間の上限は無く、読み進めれば最初のポストまでたどれる。

## 業務イベント

この資料が持ち主の業務イベントは無い。ホームタイムラインを読んでも、業務の状態は何も変わらないからである。何が見えるかを変えるのは、ポストの業務の「ポストした」と、フォローの業務のフォローとフォローを外す行いである。

# 概念

## ホームタイムラインに見えるポスト

ホームタイムラインに見えるポストは、読んだその時点の事実だけで決まる。投稿者が持ち主本人か、持ち主がその時点でフォロー中の相手であれば、そのポストは見える。どちらでもなければ見えない。フォローを始める前のポストも、何年も前のポストも、この条件を満たせば見える。フォローを外したあとに同じ相手を再びフォローすれば、その相手のポストは、外していた間のものも含めてまた見える。

見えるポストは新しい順に並ぶ。新しい順はポストIDの大きい順であり、ポストした時刻の順ではない。同じ時刻にポストされた二件でも、ポストIDの大きい方が先に並ぶ。

ホームタイムラインは一度に全部を読むのではなく、先頭から読み進める。読み進めるときは、前に読んだ最後のポストより古いポスト、つまりそのポストIDより小さいポストだけを見せる。こうすることで、一度見たポストが続きにもう一度現れない。読み進めている間に新しいポストやフォローの変化があっても、すでに読んだ分は変わらない。いちばん新しい様子を見たい利用者は、先頭から読み直す。

# 常に守られること

### ホームタイムラインは、その持ち主にしか見せない

ホームタイムラインには、持ち主が誰をフォローしているかがそのまま映る。他人に見せてしまうと、持ち主が誰を読んでいるかという私的なことが漏れる。

### いまフォロー中でない相手のポストは、ホームタイムラインに見せない

フォローを外した相手のポストが残ると、利用者は読む相手を自分で選べなくなる。外す前のポストも同じく見せない。

### 持ち主本人と、いまフォロー中の相手のポストは、一件も省かずに見せる

いつフォローしたか、いつのポストか、何件目かを理由に見えるポストを減らすと、利用者はフォロー中の相手が何をポストしたかを追えなくなる。

# 状態と、その移り変わり

状態を持たない。ホームタイムラインは、ポストとフォローの事実から読むたびに決まる一覧であり、それ自体が移り変わる状態を持たない。

# 業務の行い

## コマンド

なし。この業務は、ポストとフォローの業務が残した事実を読むだけである。

## クエリ

### ホームタイムラインを読む

読めるのは、登録済みの利用者本人が、自分のホームタイムラインを読むときだけである。他人のホームタイムラインを読めると、その人が誰をフォローしているかが本人の知らないうちに知られてしまう。

見せるのは、投稿者が持ち主本人か、読んだ時点で持ち主がフォロー中の相手であるポストのすべてである。フォローを始めた時刻、ポストの経過時間、何件目かでは除外しない。読み進めるときは、前に読んだ最後のポストのポストIDより小さいポストだけを見せる。並びは新しい順、つまりポストIDの大きい順で、ポストした時刻では並べない。一件ごとに見せるのは、ポストID、投稿者の利用者ID、本文である。見せるポストが一件も無いことも、正しい結果である。

一回に見せる件数（最大50件）は API の契約に置いた。キャッシュが持つ件数（最大500件）は品質要求に置いた。どちらも、見えるポストと並びを変えない。

#### 拒む理由: 他人のホームタイムラインを読む

ホームタイムラインは持ち主が誰を読んでいるかを映す私的な一覧で、その持ち主のものである。

# 同時に起きたとき

なし。ホームタイムラインを読んでも業務の状態は変わらないので、読む行いどうし、また読む行いとポストやフォローの変化がぶつかって、どちらかを通さなければならない場面は無い。読んだ時点の事実で見えるポストが決まる。

# まだ決まっていないこと

ポストした日時をホームタイムラインで見せるかは決まっていない。要件は表示する項目を挙げておらず、本文、ポストID、投稿者の利用者IDだけを仮に置いた（grill の推奨を採った）。見せるなら、一件ごとに見せる項目に加える。確かめる相手は要件の持ち主（利用者）である。

# BDD

ここまでの決まりが、具体の場面でどう働くかを示す。ポストIDは小さいほど先に作られたものとし、P-0001 のような番号で表す。

## ホームタイムラインを読む

### [BDD-001] 自分とフォロー中の相手のポストが新しい順に見え、フォローしていない相手のポストは見えない

```gherkin
Given: 利用者 U-001 は利用者 U-002 をフォロー中で、利用者 U-003 はフォローしていない
  And: U-001 はポスト P-0010 を、U-002 はポスト P-0011 と P-0013 を、U-003 はポスト P-0012 をポストしている
When: 利用者 U-001 が2026年10月1日 09:00に自分のホームタイムラインを読む
Then: P-0013（U-002）、P-0011（U-002）、P-0010（U-001）の順に、それぞれの本文と一緒に見える
  And: フォローしていない U-003 の P-0012 は見えない
```

### [BDD-002] フォローを始める前にポストされた相手のポストも見える

```gherkin
Given: 利用者 U-002 は2025年4月1日にポスト P-0003 をポストした
  And: 利用者 U-001 は2026年9月30日に U-002 をフォローし、いまフォロー中である
When: 利用者 U-001 が2026年10月1日に自分のホームタイムラインを読む
Then: 一年以上前の、フォローを始める前の P-0003 も見える
```

### [BDD-003] フォローを外した相手のポストは、外す前のものも見えない

```gherkin
Given: 利用者 U-001 は利用者 U-002 のフォローを2026年9月30日に外し、いまはフォローしていない
  And: U-002 は外される前の2026年9月1日にポスト P-0020 を、外された後の2026年9月30日にポスト P-0025 をポストしている
  And: U-001 は自分でポスト P-0021 をポストしている
When: 利用者 U-001 が2026年10月1日に自分のホームタイムラインを読む
Then: 自分の P-0021 だけが見える
  And: U-002 の P-0020 と P-0025 はどちらも見えない
```

### [BDD-004] フォローを外した後に再びフォローした相手のポストは、外していた間のものも見える

```gherkin
Given: 利用者 U-001 は利用者 U-002 のフォローを2026年9月1日に外し、2026年9月20日に再びフォローして、いまフォロー中である
  And: U-002 は2026年8月1日にポスト P-0030 を、フォローを外されていた2026年9月10日にポスト P-0031 をポストしている
When: 利用者 U-001 が2026年10月1日に自分のホームタイムラインを読む
Then: P-0031、P-0030 の順に見える
```

### [BDD-005] 誰もフォローしておらず、ポストもしていない利用者のホームタイムラインは空である

```gherkin
Given: 利用者 U-004 は誰もフォローしておらず、ポストもしていない
  And: 利用者 U-005 はポスト P-0040 をポストしている
When: 利用者 U-004 が自分のホームタイムラインを読む
Then: ポストは一件も見えず、それが正しい結果である
```

### [BDD-006] 誰もフォローしていなくても、自分のポストは見える

```gherkin
Given: 利用者 U-006 は誰もフォローしていない
  And: U-006 はポスト P-0050 と P-0052 をポストしている
When: 利用者 U-006 が自分のホームタイムラインを読む
Then: P-0052、P-0050 の順に見える
```

### [BDD-007] 同じ時刻にポストされた二件は、ポストIDの大きい方が先に並ぶ

```gherkin
Given: 利用者 U-001 は利用者 U-002 と U-003 をフォロー中である
  And: U-002 のポスト P-0061 と U-003 のポスト P-0062 は、どちらも2026年10月1日 08:00:00にポストされた
When: 利用者 U-001 が自分のホームタイムラインを読む
Then: P-0062、P-0061 の順に見える
```

### [BDD-008] ポストした時刻の順とポストIDの順が食い違うときは、ポストIDの順に並ぶ

```gherkin
Given: 利用者 U-001 は利用者 U-002 をフォロー中である
  And: U-002 のポスト P-0071 は2026年10月1日 08:00:05に、ポスト P-0072 は同じ日の08:00:03にポストされた
When: 利用者 U-001 が自分のホームタイムラインを読む
Then: ポストIDの大きい P-0072 が先に、P-0071 が後に見える
```

### [BDD-009] 読み進めると、前に読んだ最後のポストより古いポストだけが見える

```gherkin
Given: 利用者 U-001 のホームタイムラインに見えるポストは P-0080 から P-0089 までの10件である
  And: U-001 は先頭から読み、最後に P-0085 まで読んだ
When: 利用者 U-001 が P-0085 の続きからホームタイムラインを読み進める
Then: P-0084、P-0083、P-0082、P-0081、P-0080 の順に見える
  And: すでに読んだ P-0085 はもう一度は見えない
```

### [BDD-010] 何百件前のポストでも、読み進めれば最初のポストまで見える

```gherkin
Given: 利用者 U-001 のホームタイムラインに見えるポストは P-0001 から P-0600 までの600件である
  And: U-001 は先頭から P-0101 まで、500件を読んだ
When: 利用者 U-001 が P-0101 の続きからホームタイムラインを読み進める
Then: P-0100 から P-0001 までが新しい順に見える
  And: 500件を超えたことを理由に、見えるポストは減らない
```

### [BDD-011] 他人のホームタイムラインは読めない

```gherkin
Given: 利用者 U-001 は利用者 U-002 をフォロー中である
When: 利用者 U-003 が利用者 U-001 のホームタイムラインを読む
Then: 何も見えない
  NOTE: Rule: 他人のホームタイムラインを読む
    Reason: ホームタイムラインは持ち主が誰を読んでいるかを映す私的な一覧である
```
