# ホームタイムラインのクエリデータモデル

利用者が自分のホームタイムラインを読むとき、どのポストが見え、どの順に並ぶかが、ポストの業務が残す `posts` と、フォローの業務が残す `follows` の二つだけで実現できることを確かめる。新しいテーブルや列は要らない。投稿者が読む本人か、読む本人がいまフォロー中の相手であるポストを選び、`post_id` の大きい順に並べれば、業務知識が決めた表示対象と並び順どおりに返せる。

## ポストと、いまのフォローだけを読む

| 読むテーブル | 持ち主の資料 |
|---|---|
| `posts` | [ポストのコマンドデータモデル](../ポスト/command-data-model.md) |
| `follows` | [フォローのコマンドデータモデル](../フォロー/command-data-model.md) |

### ホームタイムラインを読む

`follows` から、`follower_user_id` が読む本人で、`status` が `following` の行を選び、その `followee_user_id` をフォロー中の相手とする。`status` が `not_following` の行、つまりフォローを外した相手はここで外れる。いつフォローしたかは `follow_base_events` にあるが、表示対象を変えないので読まない。

`posts` から、`author_user_id` が読む本人か、フォロー中の相手のどれかである行をすべて選ぶ。ポストした日時やポストの件数では絞らない。読み進めるときは、さらに `post_id` が前に読んだ最後のポストの `post_id` より小さい行だけに絞る。並べるのは `post_id` の降順で、ポストした日時（`post_base_events` の `occurred_at`）は使わない。返すのは、ポストID（`post_id`）、投稿者の利用者ID（`author_user_id`）、本文（`body`）である。

一回に返す件数は、業務知識が API の契約に置いた値なので、この資料では使わない。以下の取得結果は、見えるポストを全部並べたものである。

業務知識の BDD-007（同じ時刻の二件）と BDD-008（時刻の順とポストIDの順が食い違う二件）は、どちらも「並びは `post_id` だけで決まり、ポストした日時を読まない」ことを示すので、この資料では BDD-007 の一件にまとめた。他人のホームタイムラインを読む BDD-011 は、読む人が持ち主本人かを確かめる段階で拒まれ、データを読むところまで届かないので対象外にした。

## 未決

ポストした日時を見せるかは、業務知識で未決である。見せることに決まれば、`post_base_events` の `event_type` が `created` の行の `occurred_at` を `post_id` で結び付けて返せるので、コマンドデータモデルへの差し戻しは要らない。確かめる相手は要件の持ち主（利用者）である。

## BDD

### [BDD-001] 自分とフォロー中の相手のポストが post_id の降順に返り、フォローしていない相手のポストは返らない

```gherkin
Given: 利用者 U-001 は利用者 U-002 をフォロー中で、利用者 U-003 はフォローしていない
  And: U-001 はポスト P-0010 を、U-002 はポスト P-0011 と P-0013 を、U-003 はポスト P-0012 をポストしている
When: 利用者 U-001 が2026年10月1日 09:00に自分のホームタイムラインを読む
Then: P-0013、P-0011、P-0010 の順に返る
  And: フォローしていない U-003 の P-0012 は返らない
```

#### データの状態

**Before**

**`follows`**

| follower_user_id | followee_user_id | status |
|---|---|---|
| U-001 | U-002 | following |
| U-003 | U-001 | following |

**`posts`**

| post_id | author_user_id | body |
|---|---|---|
| P-0010 | U-001 | 朝ごはんを食べた |
| P-0011 | U-002 | 雨が降ってきた |
| P-0012 | U-003 | 新しい本を買った |
| P-0013 | U-002 | 傘を忘れた |

**取得結果**

| ポストID | 投稿者 | 本文 |
|---|---|---|
| P-0013 | U-002 | 傘を忘れた |
| P-0011 | U-002 | 雨が降ってきた |
| P-0010 | U-001 | 朝ごはんを食べた |
